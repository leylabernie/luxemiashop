# Meta checkout diagnostic runbook

Purpose: investigate Commerce Manager's repeated subtotal warning without recording checkout session credentials. These changes do not establish what Meta's server saw on a previous run. Meta's currently imported catalog and its own computation are not exposed by this instrumentation.

## Enable temporarily

1. Merge and deploy the diagnostic changes to production; verify the deployed commit. Edge logs and function logs must both be accessible in the Vercel project.
2. In Vercel production environment variables set `META_CHECKOUT_DIAGNOSTICS` to `1` and `META_CHECKOUT_DIAGNOSTICS_UNTIL` to an ISO 8601 UTC timestamp no more than 24 hours ahead (for example, one hour from now). Redeploy as required for Vercel environment variable changes. Logging is off unless both values are valid; after the deadline it stops automatically. Remove both variables and redeploy after the investigation.
3. Record the test start and finish in UTC. Trigger a new Commerce Manager validation; it may be asynchronous. In Vercel runtime logs search `[meta-checkout-diagnostic]` over that window. Share only redacted diagnostic events through an appropriate secure channel; do not share session tokens or cookies.

`edge-request` means the request reached the site's middleware; it does not record or prove the downstream status. `function-response` means the request reached the translator function. A request that uses a handle/hash rather than a numeric variant list, has `review` or `context`, or fails the Vercel rewrite pattern can instead reach the SPA, in which case no translator event should be expected. Requests handled elsewhere, such as a Shopify checkout page, cannot be captured by this site function.

Both events contain time, method, the numeric product list when safely representable, parameter presence flags, and only an allowlist of headers: user-agent, accept, accept-language, content-type and x-vercel-id. Cookies, authorization, forwarded IPs, raw query strings, coupon values and attribution are never logged. Header values are bounded and sanitized. The function event records the requested variant IDs and quantities, the returned Shopify line prices, titles and IDs, Shopify `subtotalAmount` and `totalAmount`, response status and known application-set headers. Its body is a redacted reconstruction with checkout URL replaced; `bodySha256` hashes the exact response body bytes served by the function (empty for HEAD). 302 events identify the type of destination but not the checkout URL. These logs are not a byte-for-byte capture of platform-injected headers or the sensitive checkout URL.

Compare the timestamp, user agent, method and request IDs where available. For a 200 event, compare the exact requested IDs and quantities against `shopifyLines`, `shopifySubtotal`, `shopifyTotal` and displayed subtotal. A `shopify-cart-unavailable-permalink` event means the function emitted a 302 fallback; it does not identify the underlying Shopify failure or reveal the subsequent Shopify response. If the edge event has no matching function event, inspect the routing and the request shape instead of assuming the summary was served.

Separately inspect/export the **actual catalog items imported by Meta** at validation time, including ID, variant, currency, price, sale price, availability, data source and last successful import timestamp. Compare those records to the requested IDs and logged Shopify amounts. A public feed or browser preview alone cannot prove what Meta's validator used. Continue to treat the warning as unresolved until Commerce Manager reports PASS.
